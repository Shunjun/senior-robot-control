# Control protocol v1

JSON frames are limited to 65,536 bytes. All fields are required; unknown fields,
non-finite numbers, unsupported versions and unsupported message types are rejected.
Each frame identifies the robot, session, connection epoch, request and sequence,
and carries an `expires_at` timestamp and typed `payload`. The currently supported
request types are `control.acquire`, `control.release`, `drive.velocity`,
`drive.stop`, `safety.estop`, `safety.reset`, `navigation.start`,
`navigation.cancel`, and `navigation.resume`. The velocity payload contains
`vx` (metres per second) and `wz` (radians per second); the other payloads are
empty objects. Lateral velocity is not supported.

Parsing does not authorize a command or establish freshness. Consumers must verify
authentication, connection generation, sequence and clock synchronization, then
calculate a local monotonic deadline. An untrusted remote timestamp must never be
compared directly to the robot's monotonic clock. Timing defaults are simulation
parameters and are not a physical braking guarantee.

Responses use type `response`, with a payload containing `request_type`, `ok`,
optional `error` (a stable error code), and optional `operation_id`. A successful
response cannot carry an error and a failed response must carry one. Responses
never include exception text or submitted values.

Configuration is explicitly loaded with defaults < YAML < mounted `SENIOR_SECRET`
file < `SENIOR_` environment variables < CLI overrides. Nested environment names
use double underscores, for example `SENIOR_DEVICE__TOPICS__CMD`. Nested mappings
merge recursively. No current-directory `.env` is loaded. The `agent` role owns
its device profile; `cloud` rejects it. Hardware requires a nondegenerate footprint
and nonempty frame and topic mappings.

`sensor_coverage` maps configured sensor topic keys to horizontal field-of-view
spans in radians, greater than zero and at most 2π. A hardware profile requires
`scan` coverage and its corresponding topic; every coverage entry must have a
topic. Simulation may omit coverage initially. A configured span alone does not
qualify motion or authorize reversing: Task 3 must evaluate actual per-ray
observations, coverage and occlusion.
