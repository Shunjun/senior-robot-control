# Control protocol v1

JSON frames are limited to 65,536 bytes. All fields are required; unknown fields,
non-finite numbers, unsupported versions and unsupported message types are rejected.
Each frame identifies the robot, session, connection epoch, request and sequence,
and carries an `expires_at` timestamp and typed `payload`. The currently supported
request types are `control.acquire`, `control.release`, `drive.velocity`,
`drive.stop`, `safety.estop`, and `safety.reset`. The velocity payload contains
`vx` (metres per second) and `wz` (radians per second); the other payloads are
empty objects. Lateral velocity is not supported.

Parsing does not authorize a command or establish freshness. Consumers must verify
authentication, connection generation, sequence and clock synchronization, then
calculate a local monotonic deadline. An untrusted remote timestamp must never be
compared directly to the robot's monotonic clock. Timing defaults are simulation
parameters and are not a physical braking guarantee.
