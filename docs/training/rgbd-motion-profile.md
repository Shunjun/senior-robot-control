# RGB-D motion research profile (incomplete D1 candidate)

This module is an offline research candidate, not a qualified motion source. It is not wired into ROS, Fusion or Gate. No profile, hardware, physical coverage or systematic error limit has been independently validated; `hard_error_qualified` is always false. A validation reference in the current provisional interface is caller-supplied text, not evidence checked by this module. The synthetic tests do not qualify a real deployment or complete Task 15.

The intended operating domain is a controlled SIM scene with independently declared static background, bounded dynamic/unknown fractions and occlusion, sufficient distributed non-repeating texture at multiple depths, bounded camera speed and exposure change, and independently verified registered, rectified, synchronized optical-z RGB-D and TF calibration. These bounds and empirical error limits have not yet been established. Two images alone cannot distinguish camera motion from motion of an entire scene. Missing detections do not prove a static world. Known dynamic and unknown regions must be independently and conservatively excluded in both frames; exclusion must not depend on this same estimate.

The provisional fit uses single-scale, capped ORB features, mutual ratio matching, actual per-pixel depth on both frames, PnP RANSAC and held-out grid depth/reprojection checks. Its pixel and residual thresholds are experimental fit filters, not certified error bounds or covariance. `camera_transform` maps C1 coordinates into C2; `camera_to_body_transform` computes B2←C2 · C2←C1 · C1←B1. No interpolation or extrapolation is offered.

Before runtime integration, the contract still needs externally verified stream ownership and full calibration/encoding/ROI/distortion/TF metadata and deadlines, authenticated registration, independent mask provenance and audited descriptor support, calibrated profile bounds, broader degeneracy/stability and dynamic-dominance evaluation, asynchronous in-flight revocation, target-device ABI/resource qualification, and separate independent truth evaluation. These gaps prohibit safety use even if a synthetic pair returns `candidate`.

The current interface records profile bounds and a validation reference as declarations only. It checks the stated calibration epoch, the area of independently supplied exclusions, and estimated translational speed; it cannot measure the true unknown dynamic fraction, complete occlusion, true speed or systematic error from two views. The narrow input contract accepts only mono8 and registered 32FC1 optical-z depth on a rectified full-frame grid with unit binning. These caller-supplied metadata still require authentication at the runtime boundary. An explicit invalidation method clears the retained frame when a source or TF disappears; the current serial estimator has no asynchronous pending work to cancel.

The estimator produces camera-relative motion only. The separate body conversion function verifies the coordinate direction using supplied extrinsic matrices; the resulting body transform is not a published observation and is not bound to original, time-valid TF captures. D2 must bind both extrinsics to authenticated TF identities, epochs, capture times and original deadlines before any body observation can be consumed. `RawCaptureAdmission` checks structural identity and receipt fields here; actual unique DDS endpoint and source ownership must be verified at D2's fenced receiver. The fit applies a local pose-Jacobian singular-value ratio and two deterministic spatial-group PnP fits as experimental rejection filters. Translation columns use J_t times median depth, corresponding to the dimensionless parameter t / median depth; the Rodrigues parameter domain is limited to rotations below π/2. Group agreement is not statistically independent evidence or an error bound. These checks only detect some ill-conditioned and unstable configurations; their thresholds need separate scene and sensor validation.

The serial estimator retains per-stream sequence, capture stamp and both original first-receipt frontiers across invalidation. It accepts a new generation or an explicitly changed source/bridge lineage only under the module’s replacement rules and retires prior identities, raw GIDs and replaced bridge boots/GIDs. At 64 retired identities per stream it fails closed. Restarting the estimator loses this in-memory history: D2 must retain and enforce the runtime generation/ownership fence across process restarts. Source fields are caller-supplied until the D2 fenced receiver authenticates them.

Frame dependency identities must be an immutable tuple of 1–64 nonempty strings, each at most 256 UTF-8 bytes; mutable lists and iterators are rejected without iteration. Calibration ROI and binning, output pairs and output matrices likewise require immutable tuple structures, while metadata scalars and captured headers are type-checked so mutable containers cannot be retained through a nominal scalar field. Pixel arrays remain snapshots backed by immutable bytes. This constrains local representation only and does not authenticate any supplied identity.

Four structurally valid, synchronized raw headers advance the per-stream source frontiers before profile, calibration, pixel or fit eligibility is considered; malformed or untrusted headers do not advance them. For the narrow rectified SIM grid, accepted intrinsics additionally require principal point inside the image, horizontal focal length between 0.1 and 10 image widths, and vertical focal length between 0.1 and 10 image heights. These are representation guards, not proof of calibration. The estimator checks finite intermediate numeric arrays and converts specifically identified OpenCV and numerical solver failures to unavailable. The independent camera-to-body utility rejects nonfinite or overflowing transforms.

If a capture's body cannot safely be constructed as a bounded `Frame`, the externally authenticated receiver must call `observe_unusable_headers` with its four original headers. This operation clears any pending pair and consumes the headers into the source frontier; the same capture cannot subsequently be offered as a valid frame, and recovery requires a later capture. Invalid headers do not advance the frontier. The normal successful path calls `offer` directly and must not pre-consume the same capture through this method.
