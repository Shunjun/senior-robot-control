# 单页驾驶台、多航点任务与遥控时序规格

状态：待审阅。本文用于确认产品行为和验收边界。

## 当前实现

- 选中车辆后的 `ControlSurface` 纵向排列驾驶、Home、地图、任务、地图管理和视频。地图栅格仍为空，地图点选目前只留在页面。
- `ScheduleEditor` 接收单个航点编号，`TaskList` 提交单元素 `waypoint_ids`。后端 `TaskDefinition`、存储和写入接口已经支持有序航点数组。快照只提供任务摘要，车端 `IpcNavigation.start()` 对缺少引用代次围栏的生产导航明确返回不可用。
- 当前速度指令受云端一次性许可的 300 ms 硬截止约束。当前成功响应表示 ROS 接纳了指令，安全门随后仍可能输出零。

## 布局与场景

采用一个车辆工作台，顶部保留车辆切换、连接状态、当前场景和急停。主区是切换式视图，操作区按场景呈现。驾驶页面没有文档级纵向滚动。任务列表和长表单可以在各自面板内部滚动，地图及任务操作栏固定在视口内。

此前纵向堆叠实现简单，但无法同时驾驶和看视频。持续并排显示所有模块会压缩主画面，尤其在手机上。本稿采用场景切换与一个主视图，保留已有工业仪表台风格。下面列出的默认视图、单点兼容和路线预览边界是本稿拟定的默认行为。

| 场景 | 主视图 | 持续可见的操作 |
| --- | --- | --- |
| 手动驾驶 | 默认实时视频，可切地图 | 前后、转向、获取与释放控制权、停车、定位辅助入口、控制反馈延迟 |
| 导航与定位 | 默认地图，可切实时视频 | 目标选择、定位提示、Home、返航、取消导航。动作按实时资格启用 |
| 任务管理 | 固定地图，任务列表与有序路线编辑器分栏或抽屉 | 创建、编辑、排序、启停、调度、任务运行状态 |
| 地图管理 | 地图及当前引用状态 | 导入、导出、清图和结果反馈。破坏性操作保留确认 |

在驾驶场景中切换地图和视频时，摇杆与停车按钮保持同一组件实例。键盘焦点离开摇杆仍触发停车。离开驾驶场景、换车、失焦、隐藏或连接失效时停止当前手势并撤销本地驾驶意图，停止或释放结果异步显示。返回场景后需要重新取得权限并主动操作。切换场景或浏览器离线本身不终止后台计划任务。车机到云端失联使正在执行的任务按现有策略停止，重连后不续跑。桌面和手机横竖屏均要同时容纳视频、摇杆和停车按钮，窄屏任务编辑用抽屉与固定操作栏。视频或地图缺失时明确显示不可用。急停区分已确认、等待确认和失联无法确认。

## 多航点任务

- 一个任务可有一个或多个航点。编辑器从当前地图的可用航点目录选择或在地图上添加，支持移除、重排、键盘操作及在地图上联动高亮。保存顺序即执行顺序。已有单点任务可原样打开、编辑和运行。
- 显示编号点和按顺序连接的**任务航点预览**。实际避障路径只有在 Nav2 提供同一地图引用下的规划结果时才标为「规划路径」。显示当前任务进度和活动航点时，同样依赖真实车端状态。
- 任务、航点目录和占据栅格都带 `map_id` 与 `reference_revision`，实时导航还需引用代次围栏。缺图、陈旧快照、缺少航点或引用变化时提示原因并阻止提交或启动。换车或引用变化隔离旧草稿，迟到的读取响应不能覆盖新设备或新引用。
- 车端继续作为数据权威。任务详情读取要包含有序航点、调度规则和自身修订号。更新沿用 `expected_revision`，冲突时保留草稿并提供重载入口。若支持点图新增，使用原子保存任务与新航点，或先显式保存航点后再将其作为已存在航点加入任务。首版采用后者，任务保存失败时已显式保存的航点仍作为普通航点可见。
- 先交付真实地图和已保存航点上的路线编辑，再接生产执行。真实地图、航点服务和 Nav2 有序执行均属于本规格的验收范围。编辑可以先于执行验收。没有真实地图来源时，测试夹具仅验证编辑器和协议，真实地图验收保持未完成。
- 生产执行按顺序通过 Nav2 执行。中途失败、取消或引用代次变化时终止当前执行，后续航点不继续。车机失联后不自动续跑。缺少生产导航或地图能力时，编辑与执行状态分别显示。

## 遥控时序与延迟显示

- 网页按住时每 **100 ms** 发送最新输入。持续速度发送与逐条确认解耦，队列只保留最新速度；停车优先。每个速度样本有车辆、租约、连接代次、手势代次和单调序号。拒绝旧序号、旧租约、旧手势和旧连接。
- 云端签发时计算 `补偿截止 = 签发时间 + 300 ms + 近期云端→车机单向延迟估计`。单向传输上限为 **500 ms**，车端按带误差边界的年龄判断，独立于浏览器到云端的延迟。车端先检查到达时仍早于补偿截止，再检查传输年龄上界不超过 500 ms。等于补偿截止已过期。
- 云端在签发时检查控制端输入的新鲜度，防止浏览器到云端排队后刷新旧输入的年龄。提议首版浏览器段同样采用有界时间换算，输入年龄上界 **300 ms**。采用四时间戳交换给出保守偏差区间。对发送方发出、接收方收到、接收方回复、发送方收到的时间 `t1/t2/t3/t4`，接收方相对发送方的偏差落在 `[t3 − t4, t2 − t1]` 内，按时钟漂移和取样误差扩大区间。多次可信样本可在共同参考时刻取交集，也可和独立同步的可信误差区间结合。时钟跳变、空交集或证据过宽时拒绝驾驶，在线状态仍独立。往返时间的一半仅可用于显示估计，不能代替年龄上界。
- 补偿只在签发时计算一次。提议使用最近 **10 秒**内至多 **20 个**可信的云到车单向样本的 P90，至少 **3 个**样本，向上取整至毫秒并封顶 500 ms。年龄上界已经计入时钟不确定性，预算不重复相加。时钟跳变或样本超过窗口时，清空补偿和驾驶资格。
- 接纳点是 ROS 仲裁器最终接受速度样本的时刻。Agent 到 ROS 的排队也计入接纳年龄。超过补偿截止或 500 ms 的样本即使已到达 Agent 也不能接纳。接纳后使用本地单调时钟，`执行截止 = max(保守换算的补偿截止, 接纳时刻 + 200 ms)`。**200 ms 是接纳后的最低计划执行窗口**，可以超过补偿截止。新指令、停车、急停、权限撤销或本地安全门可以提前结束。超过执行截止且没有新有效命令时归零。500 ms 是接纳条件，松手到归零及停稳另行测量。
- 停车关闭对应手势代次，后到的旧速度无法重新起步。执行截止从最终接纳点贯穿 Agent、ROS IPC、仲裁和安全门，各层不从转发时刻重新计时。底盘独立看门狗仍单独检查。
- 驾驶区显示「控制反馈延迟」，由浏览器自己的单调时钟测量同一指令从发出到收到安全门实际输出结果的时间。回执要能关联车辆、连接代次和指令标识，成功回执带实际输出的速度与限幅状态。对非零请求归零时报告拦截原因。安全门拦截、被更新的命令替换、执行超时和无样本各自显示，不能用 ROS 接纳确认冒充实际输出。建议展示最近成功样本，超过 **2 秒**无新样本时标记陈旧。实际车身移动仍用里程计测量。

## 验收与交付边界

- 时序覆盖 100/300/200/500 ms 边界、测量不可信、时钟跳变、延迟突增、过期包和停车先到。示例补偿截止 1650 ms 时，1276 ms 接纳保持到 1650 ms，1600 ms 接纳保持到 1800 ms，1650 ms 到达拒绝。
- 浏览器覆盖桌面与手机横竖屏的单屏驾驶、视频与地图切换、未定位辅助、切换场景停车以及过期反馈隔离。
- 任务覆盖至少三点添加、移除、重排、保存、重读及旧单点任务，含地图更新和修订冲突。生产执行必须另验证到点顺序、取消和断线。
- 先本地验证，再使用已运行的 Ubuntu 与 Gazebo 做隔离链路验证。复用构建，检查可用内存与磁盘，串行运行且回收测试进程。按当前约定排除 CI。规格和计划阶段不启动服务或修改产品代码。
