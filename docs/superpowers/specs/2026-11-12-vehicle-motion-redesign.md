## 目标与已确认要求

- 恢复默认可驾驶基线，软件和仿真支持 **5 km/h = 25/18 m/s**。用户最初的 5 m/s 已更正，后续任务、测试、文案均使用更正值。真车能力按适配和实测单独报告。
- 网页只表达方向、力度和高低档意图；车端负责授权、速度轨迹、反馈调节和方向性避撞。导航与手动经过相同的车端约束和执行路径。
- 用户进一步明确：除手动驾驶外，网页发布的是延迟不敏感的任务；车端接收后按任务自身生命周期执行，不依赖网页低延迟或持续在线。急停、取消、手动接管是控制事件，不能排在长任务后等待。
- 清理过度复杂的网页延迟判定，网页仅展示连接延迟。网页 RTT、浏览器时钟校准或往返挑战不再作为驾驶/任务的资格门槛。保留车端必要的手动意图断流处理、传感数据时效、来源隔离与任务去重。
- 优化网页状态组织，避免矛盾状态堆叠；支持在网页直接查看车端日志。
- 两档角速度请求上限由网页车辆设置分别配置，不写死为 1 rad/s；支持通过网页管理选定的车端运行属性，车端校验、持久化并回报实际生效配置。
- 真实车身运动使用激光、质量合格 GPS、IMU 和轮速多源估计；GPS 不保证可用，允许内部限速的轮速退化。轮速受滑移影响，不能冒充独立真值测速。
- 正常启动和减速平滑；普通障碍根据方向、距离及运动状态逐渐限速，在接触前停住。前向被阻不锁死后向，后退仍要求后方可观测且空间可行。转弯检查整个车体的扫掠范围。
- 普通避障停车与用户急停分开。网页支持软件急停复位；复位后静止待命，不恢复旧指令。导航遇障碍应重新规划，确实无路可走才等待或报告失败。
- 用户允许考虑在线估计当前加减速能力，不使用固定停车距离；建议约 5% 车体碰撞几何余量。
- 反向制动只能作为大误差、普通制动不足情况下的可选增强，不是普通减速动作；避免瞬时反转和电机冲击。具体适用性须核实驱动与固件。
- 总负责人亲自审阅实际 diff；复杂分支优先用适当模式组织，遵守单一职责，不把模式数量作为质量指标。

丰富地标场仅作标定基线，保留长直、重复与弱特征走廊的失败证据；不得以改场地消除产品风险。验收覆盖狭窄/转弯、前后障碍及可退方向、滑移/摩擦差异、动态障碍，以及 GPS 有效/失锁/漂移、激光测速失效、组合失效和恢复。每项区分真实 Gazebo 物理/传感器生成与明确注入故障；理想 GPS 或注入速度不能作为硬件精度证据。激光/GPS 缺失、障碍感知健康下的受限轮速行驶及恢复必须是有效正例，无方向感知受控停车是负例。具体任务、可实施层次及留出方案见实施计划；本轮有界标定不等于完成整个矩阵。

## 职责与数据流

网页意图或导航目标速度 → 仲裁 → 方向性运动约束与轨迹规划 → 车体反馈控制 → 最终约束核验 → 底盘速度接口。

显式急停拥有最终输出覆盖权；普通停车仍由车端控制周期持续推进减速，不因网络入口停止发命令而停止执行制动。下游看门狗承担进程/通信故障兜底，其物理行为另行验证。

| 单元 | 单一职责 | 输入与输出 |
| --- | --- | --- |
| 意图解析与仲裁 | 选择有效控制源，拒绝旧命令 | 标准化摇杆、档位、来源、序号和有效期 → 有效运动目标 |
| 运动估计适配 | 给出带时间和误差的车身运动 | 激光区间估计、质量合格 GPS 速度、IMU、轮式反馈 → 带来源模式、年龄与不确定性的车体运动 |
| 响应模型 | 管理标定响应和在线观测 | 命令历史、独立运动观测 → 适用条件、响应界、证据年龄 |
| 方向约束策略 | 判断当前可执行的运动集合 | 足迹、障碍、运动、响应模型 → 可行线/角速度组合与原因 |
| 轨迹与反馈控制 | 平滑跟踪受约束目标 | 目标、实际运动、约束、dt → 底盘目标速度 |
| 运行状态机 | 管理运动、停车、故障及恢复 | 意图/故障/急停事件 → 运行模式和允许操作 |
| ROS/硬件适配 | 转换消息并执行唯一最终输出 | 受约束速度 → `/cmd_vel` 与执行回执 |

使用组合组织策略，不建立复杂继承体系。状态转换集中声明；节点只做接线、时钟和消息转换。方向约束不能仅分别截断 vx/wz 后假设组合仍安全，最终核验必须覆盖组合轨迹和当前实际惯性。

## 闭环与制动

负责人选定的仿真产品默认值：低档 **2 km/h = 5/9 m/s**，高档 **5 km/h = 25/18 m/s**；摇杆分别提供 [-1, 1] 线性力度和转向意图，车端映射。两档线速度和角速度请求上限可在网页车辆设置中分别修改；角速度初始默认均为 1 rad/s，该值不是写死的运行规则。参数范围由车端能力配置给出，低档线速度不得高于高档。档位或配置变化仍经过轨迹控制，不产生速度阶跃。车端根据轮距和执行器限值约束线/角速度组合，必要时同比缩放请求以保持曲率，并由方向扫掠约束继续收紧；不能为容纳满杆组合擅自提高电机能力参数。UI 展示实际受限原因。默认数值为负责人提案，可配置角速度为用户明确要求；实车能力配置与测试参数分离。

保留现有 STM32 固件及底盘速度接口，不修改下位机内环。按用户要求，仅尽力利用现有资料核实电机轮速闭环；找不到匹配目标车辆的证据就记录“未确认”，不作为本轮设计、开发或仿真验收的阻塞项。当前能确认的是厂家 C30D 教学例程有编码器反馈和增量 PI，不能据此断言目标 senior_4wd_dl 当前烧录固件的具体实现。上层输出机体速度目标，不声称具备扭矩或逐轮控制接口，也不依赖已知的底层 PID 结构；外环先采用受限的比例/PI 方案评估，控制周期与增益由可观测的整体响应和延迟试验决定，不预先堆叠 D 项。

轨迹规划约束速度、加速度和变化率；外环处理扫描测量区间、年龄和时钟，避免把低频延迟观测当当前真值。约束饱和、障碍阻塞、停车及模式切换须防止积分累积。地面滑移时不能为了追上目标持续抬高驱动。

正常停车不下发突变的反向目标；切换前进/倒退先制动，再在已确认接近静止后改变运动方向。近零区设置可解释的死区与静止判据，避免来回抖动。

反向制动为负责人建议的后续独立能力：首版不实现、不提供虚假的启用开关，不作为首版通过的必要条件。硬件能力核实后再定义独立制动契约及验收，不能先假定 `/cmd_vel` 能可靠表达反向扭矩。大误差只是必要条件之一，还须确认普通制动不足、运动估计可信、驱动支持及无明显滑移，并限制幅度、变化率和持续时间。状态机决定是否允许，PI 不得自行跨零产生反转。若硬件接口无法可靠表达该能力，明确不支持，不以负速度命令冒充刹车接口。整份设计获批已包含首版后置反向制动的范围选择；这不是批准启用反向制动。

## 动态停车范围与在线响应学习

车体几何暂按长宽各乘 1.05、围绕足迹中心缩放解释用户的“约 5%”，不是体积乘 1.05；需包含实际附件。几何余量、测量误差、时延与停车位移分别记账，避免重复膨胀。

停车范围依据当前模式支持的运动估计及不确定性边界、端到端延迟及保守响应模型动态计算。恒定减速度公式只可作可解释的简化对照；实际验证包含执行器滞后、减速度建立过程、转向和打滑。没有有效观测的方向不能被标成无障碍。

在线模型从自然发生的加减速中估计响应与变化趋势；不主动对行驶中的真车施加极限制动试探。普通缓刹不能证明最大制动力，也不能单独支撑提高可保证的制动下界。制动变弱及时收紧；变好需足够证据，且不得超过已验证的适用范围。模型过期、环境突变或观测退化时降级。初始仿真模型采用明确标记的测试参数，使默认基线可运行，不用缺失的实车标定阻塞整个仿真；实车参数单独管理。

首版实现多源车体反馈、受限轮速退化、经过验证的初始响应模型及动态限速，对应下文交付阶段 2 至 5。在线估计模块随后验证，不能成为首版基本驾驶的额外放行门槛。

运动估计适配层独占“区间平均 → 当前运动上界”的转换，统一记录观测区间、年龄、协方差和加速度变化界。响应模型仅提供有适用范围的参数，不重复膨胀速度；下游消费带计算时刻和有效期的上界，不再次累加同一年龄项，过期时重新请求计算或进入停车。验收逐项核对误差预算，防止重复记账。

### 多源车体测速与受限退化（用户修订，2026-11-13）

2026-11-13 纯模块派单时，负责人批准 T3a 限定例外：T1 正式边界未冻结时，可先实现不接输出、显式注入配置的源准入、观测适配和参考模式。Observation 保留原 ROS 区间/steady 接收、frame、epoch/序号、质量及协方差依据；MotionAssessment 组合来源模式、恢复阶段、年龄、目标降级 cap 和界支持状态。BodyMotion.upper 可为 None，qualified 不等于有确定性当前真速界或运动许可。T3a 不把固定优先级参考选择称为数值融合；该阶段T3b已获准实现不接输出、显式注入配置的异步数值融合离线链，不受29项待测值阻塞；生产定量界仍待适用实测依据，后续获批隔离仿真接线例外见前述计划与阶段索引。不同观测窗口不直接拼成一个区间平均，IMU 未处理重力/姿态/零偏时不积分车速；恢复 cap 的平滑归 T5，障碍方向许可归 T4。合成配置不冻结实测参数，不作为实车/5kmh或生产资格。

测速融合激光局部运动、质量合格的 GPS 速度、IMU 与轮式反馈，不完全依赖激光。GPS 可缺失；目标设备型号及是否提供可靠速度待核实，不假设 RTK、双天线或厂家示例驱动即为实装能力。各源保留 ROS 观测区间、接收 steady 时间、来源代次、有效性、协方差及其依据；GPS 的 ENU 速度须经已知姿态/坐标系和时序转换，不能把定位差分或驱动写死的协方差当精度证明。估计适配层统一负责质量、时效、源切换和不确定性传播，缺源不得无限阻塞控制周期。

允许多源健康、GPS 辅助、受限轮速退化及不可用等可解释模式。激光测速失效但障碍感知健康时，可按合格 GPS 或受限轮速继续行驶；激光和 GPS 都缺失也不自动永久禁行。轮速退化是可行驶模式，使用内部可配置的降级速度上限、方向/曲率限制及持续滑移/执行异常监督；数值须经对应摩擦、场景和失效组合测量后冻结，不新增网页参数。轮速与真实车体运动会因滑移分离，不能沿用独立测速健康时的误差，也不能自动宣称真实速度上界可靠；无法支持受限运行风险边界时受控停车并报告原因。

激光运动估计失效与障碍感知失效分开。GPS/轮速不能替代障碍探测；继续运动仅允许有健康感知支撑、停车与扫掠空间可核验的方向。无可用方向感知时受控停车，不借用用户急停锁存。源恢复需连续合格、来源一致、时钟推进正常的证据；初始参考为至少 5 份、跨度至少 0.5 s，按实测频率核验。估计与模式上限平滑恢复，轨迹控制防止恢复瞬间速度跃升，不把旧估计重新计时。手动 authority 过期和任务接管语义不因源恢复改变。

## 停车、恢复与网络语义

| 原因 | 行为 | 恢复 |
| --- | --- | --- |
| 松杆/正常停止 | 关闭整个手动 authority，车端执行平滑减速 | 真实 release 事件后可准备新授权；收到当前回执、建立中立基线后的真实新按下才可控制 |
| 普通障碍 | 只约束危险运动；必要时受控停住 | 障碍解除且意图仍有效可继续；其他安全方向可用 |
| 手动意图过期/断网 | 永久关闭原手动 authority，本地持续减速到静止 | 不因重连自动准备授权或续跑；需明确新操作取得新授权及回执后的新输入边沿，旧指令不重放 |
| 已接受导航任务执行中断网 | 继续本地任务，自主避障与重规划；感知、执行故障和急停仍生效 | 重连同步任务身份、进度与终态，不重新提交或重复执行任务 |
| 测速源退化 | 按多源质量切换至 GPS 辅助或受限轮速；无法支持受限边界时受控停车 | 连续健康证据与平滑恢复，不借用用户急停锁存 |
| 障碍感知失效 | 仅保留健康感知支持的可行方向；全向不可用则受控停车 | 按方向恢复观测，不将 GPS/轮速当障碍探测 |
| 严重执行故障/碰撞迫近 | 根据已验证能力立即制动并报告故障 | 按故障状态恢复，不能自动掩盖真实故障 |
| 软件急停 | 持久锁存并覆盖运动输出，禁止普通控制 | 有权限且匹配当前急停版本的网页复位；静止待命 |
| 实体急停 | 保留硬件优先权 | 实体释放且车端确认后才可恢复，网页不得越过硬件 |

恢复决策：按上述多源模式和方向感知判断受限继续或停车，禁止把激光测速失效一概锁死。首次恢复条件为至少 5 个连续合格、来源一致且时间推进正常的估计，覆盖至少 0.5 s；这是仿真初始恢复参数，须在实施验收前按测得频率验证。恢复后已接受任务可由车端重新规划并继续；手动必须松杆后重新输入，连续发送的旧按住动作不能自动续跑。方向性障碍停车不要求该故障恢复流程。

真实执行故障（例如持续打滑、堵转或制动跟踪失败）保持独立故障状态，不借用用户急停锁存。网页提供单独的故障恢复请求；只有故障原因解除、健康证据满足条件且车辆已确认静止才可接受。恢复不自动启动手动或任务运动，已接受任务保留为暂停待继续，不将可恢复故障等同于任务取消；取消由独立事件决定。软件急停复位不能顺便清掉执行故障。具体故障检测阈值通过有效刺激与负对照标定，不能只改名保留旧误锁存。

安全制动可能比舒适减速更急，不等于进入用户急停。复位/重连不重放旧手动轨迹或最后一条速度；已接受任务按其车端生命周期推进，重连只同步状态。导航短时被障碍约束不永久撤销资格，Nav2 负责重规划；感知真实失效则另行处理。

手动接管的负责人默认选择：暂停当前运动任务，保留任务身份、已完成进度和未完成目标；撤销导航执行器旧输出后才允许手动输入接管，不并行执行两个运动源。松杆、释放控制权、手动断网或重新连接均不自动恢复任务。用户明确点击“继续任务”后，车端按当前实际位姿和当前地图重新规划未完成部分，不能重放接管前的速度轨迹，也不重复已完成动作。只有显式取消才取消任务；到达、完成与接管并发时，以车端串行状态转换和持久进度为准，不复活已完成任务。此规则针对与驾驶互斥的运动任务，查看日志等只读操作不暂停任务。

**用户已确认：导航运行中网页或网络断开，继续已接受的导航任务，由车端自主避障。** 任务接受状态与网页连接、手动租约生命周期分离；断网不撤销正在执行的导航任务。导航内部速度样本仍须满足本地新鲜度与来源检查，不能把自主继续等同于持续执行最后一条过期速度。离线不接受新的远程任务；重连以车端任务身份与进度为准，防止重放与重复执行。实体/软件急停、感知失效和执行故障仍按各自状态机处理。该决定只授权继续已接受任务，不扩展到离线自动启动其他定时任务，也不默认授权进程重启后自动续跑。

用户后续将上述原则扩展到所有非手动任务：已接受的任务由车端拥有，按各自已定义的执行或排队语义推进；不把手动指令短有效期套用到任务。任务提交使用稳定任务标识和幂等接收结果，区分发送中、已接受、执行中、成功、失败、取消及状态未知。响应超时表示网页尚不知道结果，不代表车端失败；重连先查询，不重复执行。新任务在离线网页中不伪装成已接受。已有定时任务调度和进程重启续跑语义需单独核对，不以网络策略变更暗中扩大。

删除延迟逻辑前列出每项调用方：网页 RTT 展示、本地手动活性、传感时间语义、来源代次、任务幂等分别归属。浏览器校时、延迟挑战/资格和冗余拦截在迁移后删除；不能仅把旧门槛改为永远通过。手动控制使用车端本地单调时间管理活性、最新意图与有界待处理消息；需测试网络堆积后迟到意图不能重新驱动车辆。具体输送机制按实施计划及下述负责人实施细化执行，不再向网页暴露一套驾驶资格挑战流程。

### 手动输送机制：负责人实施细化记录（2026-11-13 历史时点）

本节保留当时 T2a/T2b 纯模块及后续接线的阶段描述，不构成当前全面接线禁令；T3a/T3b 纯模块阶段同理。当前显式隔离 simulation-only/unvalidated 接线例外按前述实施计划与阶段索引执行，不代表正式边界已冻结或允许实车运行。

以下是负责人在既有获批设计范围内对 T2 模块拆分和接线语义的实施细化，不是用户逐项批准记录。`control.acquire` 由车端生成不可预测的 authority，返回 `prepared` 回执；此时没有运动、held target 或短运动 TTL。准备授权受当前认证连接生命周期及有界配额约束，正常等待不会因短运动 TTL 到期而要求反复授权，也不靠定时 acquire 或零意图心跳续命。只有当前可信上下文中的首次合法 `drive.intent` 才创建 `active` ManualSession，从该样本的车端原始接收时刻开始计算活性；准备授权本身不能输出速度。这里不声称能够推断首次样本的任意单向网络延迟。

网页必须先收到匹配当前车辆、连接、控制会话及请求尝试的 acquire 回执，再允许新的真实输入边沿。回执前已按住的输入必须真正释放，建立中立基线后再新按下；不得回放等待期间保存的输入，也不得把迟到回执、pointermove、按键重复或程序清零当成新按下。已经中立并收到当前 prepared 回执的用户，正常等待后的首次真实按下即可产生首个意图，不将该按下另作准备动作并要求再按一次。这些边沿与回执顺序由后续 UI 接线保证，纯 owner 不宣称已经证明网页事件真实性。

普通 `stop`、`release` 均关闭整个 authority，不只封闭 gesture；active 断流到期、故障或连接退役同样永久关闭它，迟到包即使 sequence 更大也不能刷新或重开。正常真实 release 事件后，UI 可明确申请新的 prepared 授权；新回执先建立中立基线，随后真实新按下才可运动。断流、网络重连、故障恢复或一直按住均不得自动申请新授权或恢复旧动作。相同 acquire request_id 与相同载荷指纹幂等返回同 identity 的当前状态，已关闭仍为 closed，不延长期限；异载荷冲突。回执及关闭记录按有界配额保留，容量满拒绝新请求，不能驱逐记录后让旧请求复活；整个旧连接命名空间退役后由代次屏障拒绝旧请求，不重新注册。

authority 绑定可信的 boot、车辆、agent_epoch、controller_generation 和 control session。controller_generation 必须由可信连接 owner 在同一 agent_epoch 内单调分配；新的 agent_epoch 可重新开始该计数。当前纯 manager 以 `(agent_epoch, controller_generation)` 的字典序判断更新上下文，该前提不能用浏览器自报数字替代。连接先退役、后显式绑定更新上下文，不能由迟到 intent 或 acquire 隐式绑定；新 boot 不恢复旧手动授权。

车端将实际处理 `now_steady` 与原始 `received_steady` 分开：先按实际当前时刻检查已有会话是否到期，到期（含等号）即永久关闭，再处理后来包；未来、非法、过老或不符合接收顺序的时刻均拒绝，拒绝不刷新租约。唯一 session 截止为 `received_steady + TTL`，可选的更短本段 queue cutoff 也由同一 session 统一取 min；manager 不另持一套 effective deadline。TTL 和各段预算须由测量冻结并显式注入，不使用未经冻结默认值。每段转发前检查本段原始接收年龄，同机 IPC 保留原始接收时刻及固定 cutoff，不能在出队或处理时重新盖章；不把跨机 steady 时钟直接比较，也不引入 RTT 资格或浏览器校时。

各段按有界最新样本槽及确认机制输送，不追加旧动作队列。`take_latest` 一次交付包含意图、原始接收时刻和固定 deadline 的不可变快照；后续新包不能修改已交付快照的期限。下游 held target 必须保留该固定截止，在 authority 关闭时按身份撤销；读取、tick、ack、反馈和发布均不能续期。手动失效不改变已接受 Navigation/其他任务的车端生命周期；接管暂停屏障与持续制动仍由后续 T5/T6 接线完成。

此前接线分析中的“acquire 即启动短空租约”“长等后的第一次按下只作准备再要求重按”“gesture-only stop”以及 manager 另持 effective cutoff 均不再作为当前实施建议。直接构造 ManualSession 仍保留低层构造起计的兼容语义，但 acquire 不再据此构造空运动会话。该记录时点 T2a/T2b 交付的是纯类型、会话和 authority owner；这段说明不表示协议、UI、云、Agent、ROS 或车辆输出已迁移，也不表示车辆可驾驶或已完成验收。

## 网页车辆参数设置

网页提供独立的车辆设置入口。用户已限定首版驾驶配置为五项：低档线速度上限、高档线速度上限、低档角速度请求上限、高档角速度请求上限、统一倒车速度上限。倒车实际速度同时受当前档位线速度上限和倒车速度上限约束。页面标明单位、允许范围、默认值与当前生效值，线速度以 km/h 展示，传输和控制内部统一使用 SI 单位。角速度以 rad/s 展示并可辅以 °/s 换算。

首版日志配置包括日志级别、日志保留时间，以及临时调试日志开关和自动恢复时长；临时调试结束后恢复开启前的常规级别，车端持有恢复期限，网页断开不影响自动恢复。日志设置同样在车端持久化，由网页读取和修改。用户明确不开放磁盘空间上限设置；内部日志轮转、缓冲和资源保护仍保留，不作为网页配置项。日志设置可在运行中修改，不触发运动状态变化。

常规加速度/减速度、加速度变化率、摇杆死区/灵敏度、避障参数、导航容差和手动断流时间本轮均不开放网页配置；这些值仍由车端实现和经验证的配置管理。不能将之前的参数建议自动扩展为首版需求。

设置提交是延迟不敏感的配置任务，具有请求标识和配置版本。车端是配置权威来源：校验权限、数值、上下限、参数组合及预期版本，整组原子应用并持久化，成功后回报生效值与新版本。拒绝时保留原配置并给出可读原因，不能半组生效。多人或多标签并发修改出现版本冲突时刷新并提示，不静默覆盖。网络超时显示结果待确认，重连查询结果，不把“发出请求”显示为“保存成功”。

首版上述五项驾驶参数仅在车辆确认静止且没有执行中的运动任务时应用；导航须先暂停，手动须先松杆并停稳。运行中提交明确拒绝并提示先停稳，不暗中排队到未知时刻生效。驾驶设置和日志设置分组提交，日志修改不受停稳条件限制。配置不会触发起步，恢复运动需要遵守当前任务/手动状态机。配置重启后保留；恢复默认值也经相同校验与应用流程，配置损坏明确报错而非使用部分字段。

车体尺寸、轮距/轮径、传感器外参、固件能力和可保证制动响应属于车型/标定参数；首版设置页可显示其当前来源和值，不作为普通驾驶调节项。车端 PI 增益和独立制动能力不能通过调大常规减速度自动改变。后续若开放标定编辑，应走专门标定流程；本轮不暴露任意 ROS 参数或任意配置文件编辑器。

此功能纳入交付阶段 4 和首版阶段 5 验收。覆盖两档独立线/角速度生效、倒车受档位与倒车上限共同约束、单位换算、上下限及组合错误、并发版本冲突、断线重试去重、运行中拒绝驾驶参数修改但允许日志设置修改、车端重启持久化、恢复默认值、保存后网页回读一致、日志保留时间生效、临时调试在网页离线时自动恢复，以及设置不会绕过方向约束或触发车辆运动。网页不得出现磁盘空间上限或其他未纳入首版的参数输入项。

负责人建议采用单一车辆运行状态投影，细节由子状态解释，避免连接、任务、运动和急停组件各自推导出矛盾结论。

- 顶部连接区：在线/断线/重连中、连接 RTT、最后更新时刻。断线时清楚标记显示的是最后已知状态，不把车端仍可能执行的任务显示成已停止。RTT 是诊断显示，不是驾驶资格。
- 运行区：手动/任务模式、当前任务及进度、实际车身速度、高低档、主要受限或停车原因，以及下一步可操作项。目标意图、安全限速和实测车速可在详细诊断展开，默认不同时堆出多个混淆的“速度”。
- 急停：独立且始终可发现；锁存时清楚显示原因与复位入口。网络不可达时明确尚未获得车端确认，不能显示急停已生效。硬件急停不能通过网页强制解除。
- 日志面板：查看车端控制、导航、感知故障及运行日志；按时间、级别、模块筛选，支持实时跟随、暂停、历史分页和下载。默认提供可理解的事件摘要，完整技术日志在详情中展开。
- 日志链路：经现有车端 Agent/云端/网页认证链路访问，按车辆权限隔离。采用有界缓冲和游标，重连补读并显式标记缺失；不能让大量日志挤占控制消息或导致浏览器无限增长。禁止直接开放文件系统或任意 shell 日志命令，排除凭证/配对密钥等敏感内容。
- 关联性：任务 ID、请求 ID 和车端事件时间贯穿接受、执行、限速/停车及结果；网页从一次操作定位对应日志。展示源时间和接收时间，避免借浏览器时钟差伪造事件顺序。

前端实施前提供状态布局预览，沿用现有视觉体系，优先解决信息层级和状态一致性。样式组件化，复杂状态通过显式模型/选择器归一化，不在各组件重复写条件判断。

## 异步计算与默认基线

评估采用不可变快照和有界有效期。不得无条件重用上一份安全结论；危险变更、新障碍、急停、来源变化及时撤销，最终输出再次检查。需要证明在正常连续输入下有限时间内产出有效约束，同时旧结果不能穿透新的危险。

选用“有界快速收紧 + 异步细化放宽”：快速路径消费最新有效观测和当前运动上界，只收紧已有许可，不做高成本完整重算；异步路径合并待处理输入，仅保留最新快照。异步结果想放宽时必须通过最新快速核验、有效期和危险版本检查。快速路径覆盖不够、来不及完成或没有足够依据时进入制动，不把未知视为安全。输出只能在所许可的运动集合内；新意图超出该集合不能复用旧结果。最终核验采用同一个有界快速策略，避免把全量慢计算搬回控制线程。实施前需测出快速路径最坏耗时和适用场景，若不能满足控制周期则收缩算法范围与降速，不用更长有效期掩盖。

仿真启动配置自洽，移除与单个历史测试速度绑定的资格表达，改为可解释的参数一致性和能力检查；不能删掉全部检查或提高超时来掩盖调度停顿。记录墙钟与仿真时间推进，区分传感延迟和仿真暂停。
