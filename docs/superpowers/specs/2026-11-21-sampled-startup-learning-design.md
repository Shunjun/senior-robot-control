# 启动学习：前进期间均匀选择五帧

用户在本轮对话确认：前进与学习计算独立，前进只是验证随车稳定；从前进过程抽取4～5帧，最终采用5帧。保留与车内物体相连并伸出车外的随车部分，独立墙面保留为障碍。不再为极端平行墙面增加运动或识别条件。

本节覆盖旧设计中的“所有接纳帧都参与候选交集”“逐帧反复重验连接”“仅扫描序号相邻即可向车外无限延伸”。动作目标0.05m/s、首次成功提交后的3秒时钟、停车验证、接管及单写保存沿用原实现；学习计算不得延长动作或阻塞控制。

## 方案

1. 沿现有有界采集链路记录合法原始帧。服务封闭运动窗口及原有停车验证事实后，在运动窗口内按实际采集时间选择首、25%、50%、75%、尾五个不同的帧。中间目标相对实际可用首尾采集时间，按最近时间选择，按原顺序消除重复选择。未满五帧不发布模型，不重复同帧凑数。
2. CPU子进程只接收这五帧，保留原每批最多四帧的IPC上限。未收到完成标记时只缓存五帧以内的解码观测，不逐帧更新候选或反复求连通性。运动控制不等待计算。
3. 以首个采样帧的实际端点为固定参考。每个参考位置在其它四帧的实际命中点中均须得到1cm以内支持，使用空间索引查询，允许邻近束提供支持，不要求同数组序号。
4. 在稳定的参考回波上只做一次连接分段，从严格车内端点为种子的段保留连续车外部分。无效点、缺序号或不稳定点中断连接；相邻有效点若实际空间空隙过大，也分为不同段，不能仅因均有回波而把远墙接上车体。
5. 连接距离的实现选择：端点距离不超过实际相邻束在较近距离上的弦长，加两端各1cm的位置尺度。该固定判据复用匹配尺度，不读取全局避障误差、不膨胀车体、不新增网页/配置参数。360度首尾连接沿用原采样拓扑识别，同时应用空间间隙判断。这是负责人选择的具体实现，不代表雷达实测精度或物理连接证明。
6. 完成后沿原owner原子保存及安装不可变模型，运行只读1cm位置过滤。遮挡、漏测不撤销学习结果。

## 取舍

首尾两帧最省计算，但用户已选择五帧；全部帧逐帧交集不再是需求。五帧一次性稳定筛选加一次连接分段既符合抽样要求，也去除每帧多轮几何对象构造。不是对旧全帧模型做输出等价优化：未抽中的短暂变化不会参与结果，旧无限距离扫描段连接也被覆盖。

本轮不改原始录帧协议、不更换数据完整性/容量规则、不新增运动资格。现有录帧传输保持原样；重计算和保留的模型观测只使用五帧。后续若要停止完成后的整帧录制，是独立的传输生命周期优化。

## 后续清理覆盖（2026-11-21）

用户进一步确认删除旧逐帧算法、流式计算和全帧完整性追踪，并清理额外等帧。以下覆盖前文保留旧协议/容量完整性政策的实现说明：

- 删除 `observe`、`validate`、历史保留和候选交集循环，只剩五帧一次识别及固定结果过滤；不保留仅供旧测试调用的生产接口。
- 五帧以一个 `ComputeRequest` 提交一次，返回一个 `ComputeResult`；取消4+1分批、finish标记、累计内核状态和学习专用消息轮询实现，复用独立的通用 `ProcessWorker`，首次计算才创建资源。
- 原始帧入口仍使用有界数据小包传输，但删除传输index、stream_id、ACK前沿和全帧gap失败政策。发送缓冲保留最新16帧；服务端达到128帧时按时间顺序压缩为64帧并保留首尾。缺失未选中的扫描不单独否决学习，不能声称录下了完整原始流。
- 仍验证采样来自一致来源和几何、原采集时钟/序号不倒退、五帧互不重复；这些是样本身份要求，不是完整帧流证明。
- 删除启动前等5帧和停车后等5帧。动作仍由原有效感知与输出限制保护；只有三秒窗口结束、有原停稳事实、接收队列已经推进到该关闭时间且至少五个合法运动帧已收到，才封闭采集。接管后收到的帧不能补足此前缺失的样本。
- 三秒动作时钟、首次私有输出起算、显式接管、重新校准幂等、结果原子保存及运行期只读模型保持不变。
- 私有IPC新旧格式不能混跑，应同步更新并重启相关车端进程。磁盘 `CaptureSummary` 只读保留旧stream字段以读取既有记录；新生产路径不再写入或追踪这些字段。
