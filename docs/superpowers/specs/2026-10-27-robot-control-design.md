# Senior 小车远程控制系统设计

状态：功能清单已确认用于编写实施计划；包含计划编写期间补充的雷达自车遮挡要求。本文是实施计划的统一设计依据。

## 1. 项目目标与范围

面向 WHEELTEC senior_4wd_dl，建设车端 ROS 2 控制程序、自托管云端中转服务及中文网页控制台。保留厂商底盘、雷达和相机驱动，重写上层控制与功能，实现：

- 桌面与移动端遥控，支持手机横屏驾驶。
- 跨会话保存、加载和持续更新 SLAM 地图。
- 窄道导航、贴墙后的受控脱困与实时避障。
- 可选 GPS/RTK 地理配准、自动定位和行驶中的被动航向校准。
- 深度相机远程视频、YOLO 视觉识别及几何避障。
- 多条定时导航任务、普通导航点与特殊导航点 Home。
- 单管理员管理多台小车，支持 4G/非局域网连接。
- Linux 仿真环境中的完整控制链测试。

项目位于 senior-robot-control，原厂资料与 robot_goal_navigation 仅作参考，原目录不修改。不重写 MCU 固件与厂商硬件驱动，不包含自动充电对接。

## 2. 方案与技术基线

已选择“保留硬件驱动、重写上层系统”。连底盘串口驱动一起重写会增加协议、电机和里程计验证工作，当前故障证据不支持扩大到这一层。

技术提议：Ubuntu 22.04 / ROS 2 Humble、SLAM Toolbox、Nav2；车端代理与云端业务使用 Python，网页使用 React、TypeScript、Vite、CSS Modules。具体 ROS 插件和参数以部署版本验证，不照搬 rolling 文档配置。

已知雷达为 N10P，厂商资料中有 N10Plus 驱动入口。深度相机型号待检测，资料同时存在 Astra 系列不同配置，不能将默认配置当作实车型号。部署检测还需确认主控算力、实际 Ubuntu/ROS 版本、话题、TF、雷达覆盖、相机标定和车体附件尺寸。上述基线不是实车环境已确认的声明。

工程约束：未经要求不启动开发服务；兼容代码标注 //Compatible，Python 使用 # //Compatible；组件 props 超过三个时定义独立类型；组件样式不放入全局 CSS，通用主题与全局覆盖除外。

## 3. 系统架构与多车管理

| 层级 | 职责 |
| --- | --- |
| 厂商驱动 | 底盘串口、轮速与里程计、N10Plus 雷达、深度相机、URDF及静态TF |
| ROS 2 功能层 | 本地定位融合、SLAM、导航、脱困、几何与语义感知、速度仲裁和独立安全保护 |
| 车端代理 | 主动连接云端，命令校验、设备状态、车端数据存储、地图操作与任务调度 |
| 云端服务 | 单管理员认证、设备配对、连接管理、消息与视频信令中转、操作记录 |
| 网页控制台 | 设备选择、地图与视频、遥控、导航点、Home、任务和设备管理 |

### 3.1 身份与连接

一个服务实例由单管理员使用，不做公开注册、多用户、角色或组织权限系统。管理员凭据从部署配置注入，保留登录失败限流、会话过期和退出。

小车首次通过短期、一次性配对码注册，保存独立设备凭据，之后主动保持云端长连接和应用层心跳；掉线后退避重连，无需重复配对。设备可命名、配置、移除和撤销凭据。移除或撤销后不能继续重连访问，不能通过重复设备 ID 覆盖现有身份。

控制端验证身份后进入设备列表，可查看多台车并选择其中一台驾驶。每台车独立显示连接、定位、地图、任务、视频与传感器状态。“持续在线”表示保持连接与自动重连，不掩盖实际断网或停机。

### 3.2 命令隔离与控制权

所有状态、目标、任务、地图和视频信令绑定 robot_id。服务端与车端均检查目标设备；协议采用版本化 JSON，命令含请求 ID、会话/连接标识、序号和有效期，拒绝重复、过期和旧连接遗留命令。地图相关对象还包含 map_id 与参考版本。

控制权租约仅用于同一管理员的多个页面或终端之间互斥，不是多用户功能。一个页面同一时间只驾驶一台车；切换前停止旧车遥控并释放租约，新车重新申请控制权。不同小车的自主任务独立运行，但都必须满足各自连接与安全条件。

公网使用 HTTPS/WSS，不直接暴露 DDS 或无鉴权 rosbridge。小车主动连接使 4G/CGNAT、虚拟机 NAT 无需接受公网入站连接。

## 4. 遥控、连接与运动安全

唯一速度链：Nav2 / 遥控 / 脱困 → 控制仲裁 → 限速与加速度控制 → 独立安全门 → 底盘。任何速度源，包括恢复行为，均不得绕过安全门。底盘还必须具备命令超时停车能力，缺失时作为实车部署阻塞项。

网页按住驾驶，松开、失焦、触摸取消或页面隐藏时发送停车。车端以单调时钟执行速度命令超时，不依赖浏览器停车消息送达。急停优先并保持锁定，解除需显式操作。未验收的配置与演示模式禁止驱动真实底盘。

用实际车体多边形检查硬碰撞，另外设置随速度和制动距离变化的预警区。厂商矩形 footprint 约 0.674×0.54m，只作初值，实车附件必须计入。雷达与深度几何信息参与保护；YOLO 类别不能替代几何碰撞判断。

认证连接与应用层心跳超时、传感器过期、必要TF缺失或安全门异常时禁止相应运动。断线检测有明确的心跳周期与超时界限，不能声称物理断网瞬间即可检测。

小车与服务器连接失效后，遥控停车，自主导航、返回Home与正在执行的任务暂停并停车。先禁止自主速度输出，同时取消Nav2动作，不以取消请求尚未完成作为继续行驶的理由。重连不自动续跑中断的动作；需显式恢复并重新校验条件。网页是否打开不影响任务执行资格，关键是车端与服务端的有效连接。

### 4.1 自车回波、遮挡与盲区

实车雷达后方可能被随车移动的附件遮挡。依据URDF与实测附件形状、雷达到车体外参，在车体/传感器坐标系定义自车过滤体积和遮挡扇区；辅助观测可用于发现固定随车回波，但不能仅因长期存在或随车移动就自动忽略，以免把近距离真实障碍误当附件。过滤配置需可查看、标定与验证。

原始扫描保留用于诊断。自车命中不写入环境地图、不当作外部障碍持续锁车；被自车遮挡的区域标为未知/不可观测，不产生穿透附件的空闲射线。过滤不把量测替换为可通行的无限远。长期地图稳定性判断使用世界/地图坐标，不能把车体固定回波误认作稳定环境。

为每个运动候选检查有效感知覆盖，转向也需检查车角扫入区域。优先使用实时观测，其他传感器可补足覆盖并验证外参、量程、新鲜度及制动空间。后方局部遮挡并非一律禁止倒车：允许在下述降级策略中使用已建地图和近期观测进行受限慢速倒车；历史地图不提供当前无动态障碍的保证。定位不可靠、后方地图未知或占据、独立运动观测不足时不执行。

仿真需加入随车后部遮挡物，验证过滤不建假墙、不清除其后真实障碍，且不因过滤后无回波直接判定空闲；历史地图倒车须满足独立的降级策略。附件变化后重新标定。

### 4.2 历史地图辅助倒车与打滑、受阻检测

后方被附件遮挡时，可在地图后方已知为空闲、当前地图定位可信且存在有效独立运动观测的条件下，执行降级的短距离低速倒车。优先使用近期真实观测，并明确记录地图/观测年龄与盲区范围；未知区、已知障碍区和超出降级距离/时间预算的区域不允许进入。速度、最大单次/累计距离、时长和观测年龄门限在仿真与实车中标定，不用任意默认值声称可安全接触。

运动判断不单靠轮速里程计odom：联合有效侧向/前向雷达扫描匹配产生的独立局部运动、IMU相对角运动及可用的视觉里程计进行估计。检查数据新鲜度、时间对齐、协方差与匹配退化；不能用本来就由轮速融合得到的odom当作独立证据。雷达局部运动以连续局部参考计算，避免把SLAM回环修正当成真实车体位移。

比较轮速预测、独立实际运动与下发命令：轮子明显转动而车体位移不足、方向不一致或偏航异常时，判定运动异常，区分可判断的打滑与原因不明的受阻。结合可用电流、驱动故障或接触传感器辅助分类，但不假定现有底盘提供这些信号。静止起步、制动、低速测量噪声需设置窗口和滞回，避免正常起步立即误报。

异常立即停车并取消当前脱困动作，不自动加力或重复顶撞。不能把“没有实际移动”可靠地解释为后方碰撞，也不能把检测到移动解释为没有接触；检测具有延迟，可能在接触后才发现。网页明确显示盲区倒车降级状态和停止原因。独立运动估计退化、时间超限或新的障碍证据出现时停车；停车后的恢复需重新评估，不盲目重复。

打滑检测同样作用于正常导航、前进、转向和遥控。控制器以经质量门控的实际运动估计进行速度反馈、进展判断和脱困距离预算，轮速odom保留为输入但不是唯一位移真值。无法可信估计实际运动时停止依赖该估计的自主行为。

验收覆盖：后部遮挡且历史空闲时有界慢退；轮子转而车体不动；正常移动与轮速偏差；雷达退化；侧滑与异常偏航；起步迟滞不误判；回环跳变不算移动；盲区内新增障碍导致受阻后立即停车。最后一项验证异常响应，不宣称实现接触前的后向障碍检测。

## 5. 导航、探索与脱困

参考原型的最小复现显示：0.65m圆形包络内有障碍点时，前进、倒车和旋转均被起始时刻检查拒绝；探索也可能直接返回 unsafe_start。这是需要替换的逻辑，不是允许关闭碰撞保护的理由。

提议采用支持非圆形差速底盘的 Smac State Lattice、适配的运动原语和实际footprint，配合MPPI控制器。取消强制先原地转向的策略。探索根据方向相关可通行性选择可达前沿观察点，不再以大圆包络一律判死当前起点。具体插件能力、算力负载和参数在Humble与仿真中验证。

脱困状态：正常导航 → 受阻诊断 → 候选轨迹评估 → 有界执行 → 重新规划 → 恢复或失败。候选包括短距离倒车、小角度旋转和低速弧线，按实际空间选择，不固定强制顺序。

每条候选检查整段车体扫掠范围、当前实际速度、反应与制动距离、传感器覆盖和新鲜度。前方预警区触障不应阻止安全倒退；转向必须检查车角扫过的区域，慢速不等于可安全旋转。

仅预警余量重叠而硬边界仍安全时，可执行验证过的脱离运动。已知车体实际接触、硬边界碰撞、感知覆盖不足或定位不可信时停止并报告。限制累计距离、执行时间、尝试次数和无进展时间，防止循环挣扎。不通过清空真实障碍、缩小实际车体或关闭保护脱困。

## 6. 持续建图、地图变化与数据版本

保存可续建的SLAM位姿图及关联数据，同时保存栅格快照；采用一致快照、原子落盘、版本清单和恢复校验。重启加载旧地图后，完成重定位再继续建图。长期地图仅接收经过时序稳定性验证的障碍；实时障碍独立进入短期代价层。采用下述稳定写入与空闲清除机制，不假设SLAM Toolbox原生就能完成这些过滤。

### 6.1 稳定障碍写入与消失障碍清除

长期地图表达当前稳定环境，不永久固化第一次扫描结果。实时感知、建图候选与长期地图分层：所有有效障碍立即参与实时避障；候选通过多次有效观测、持续时间与空间一致性检验后，才允许写入长期地图。阈值可配置并通过仿真验证，单次扫描不足以确认新增或删除。

人员等明确可移动的语义类别即使短暂停留，也不写入长期地图；运动跟踪检测到的移动目标同样排除。YOLO语义、深度关联与几何时序检测联合使用，未知类别仍按几何稳定性判定。检测与跟踪可能漏检，系统以“不写入已识别移动目标”为验收目标，不声称感知能识别所有动态对象。感知降级时显示状态，并采取保守的长期地图写入策略，不影响实时几何避障。

箱子等物体若稳定存在，可在确认后进入长期地图；以后再次经过，若同一地图位置被多次可靠观测为空闲，则降低其占据置信度并最终清除。判断空闲依赖传感器有效量程内穿过原障碍区域的自由空间射线或等价的有效深度证据。无回波只能在对应驱动与测量模型明确支持该解释时使用；无效深度、视野外、遮挡、数据丢失、传感器过期或定位不可信不能作为清除证据。

新增确认与消失确认使用独立门限及滞回，减少噪声导致反复闪烁；保存观测次数、最近有效时间、占据置信度和变化来源。仅随时间推移不能删除长期障碍。实时层与长期层分别维护清除状态，长期旧占据不能阻止对已观测为空闲区域的重新评估。

建图输入过滤与自由空间证据须分别处理：剔除行人命中点不能把行人后面的遮挡区域虚构成空闲，也不能简单把过滤后的量测改成无限远。只有真实看见的自由空间才更新地图。地图持久化需包含维护稳定环境所需的状态，加载后继续一致更新。

实施计划必须明确SLAM定位/位姿图与可更新长期占据层的接口：既要保持定位所需几何约束，又要确保导航用地图、网页显示、保存导出与重载后的地图一致反映障碍新增和消失。不能仅清理局部代价地图或只修改前端画面来宣称已更新SLAM地图；若采用独立长期占据层，导出包需同时保存它及其与位姿图的坐标关联，并验证回环后的更新。

仿真验收：行人穿行及短暂停留不进入长期地图；稳定箱子确认后写入；搬走箱子并重新观测后从长期地图和导航障碍中清除；箱子被行人遮挡时不误清除；单帧漏测不删除墙体；变化在保存、导出、重载和回环后保持一致。

### 6.2 地图变化分类与参考版本

地图变化分三类：

| 类型 | 判断依据 | 处理 |
| --- | --- | --- |
| 实时障碍出现/消失 | 雷达、深度观测与代价层更新 | 避障和重新规划，不修改Home坐标 |
| 地图扩展、栅格内容更新 | SLAM地图数据变化 | 更新显示与目标可达性；宽高或栅格原点变化不等于参考坐标失效 |
| 回环几何纠正、地图切换或重置 | 后端可验证的位姿图修正，或明确的地图参考身份变更 | 检查附属导航点和地理配准；切换/重置后重新定位 |

map_id表示地图身份，reference_revision表示影响坐标解释的参考版本，数据快照版本独立记录。不能每次收到/map就使导航点失效，也不能仅凭时间戳或map到odom跳变推断回环。

回环后，优先依据可验证的关键帧关联和位姿图修正更新固定导航点，重新评估地理配准残差；不假设所有非刚性地图纠正都可用一个全局刚体变换迁移。后端无法提供可靠关联时将相关点标记待核查，不猜测坐标。目标附近暂时有障碍只表示当前不可达，不自动移动该目标。

## 7. 地理配准、重定位与GPS航向校准

### 7.1 可选GPS与地图地理配准

无GPS时使用SLAM地图坐标正常工作。有GPS时检测NavSatFix、时间戳、协方差与来源状态；RTK Fixed/Float必须由驱动明确适配，不能从普通fix状态猜测。

地理配准描述地图与WGS84/ENU之间的关系，保存datum、水平旋转与平移、高度基准、质量/协方差、来源和适用版本。一个GPS点且没有可靠绝对航向，不能确定完整配准。首版采用松耦合地理对齐，不宣称GPS参与SLAM位姿图联合优化或保证厘米级精度。

GPS失锁时，若局部定位及其余条件健康，可继续地图坐标下的任务；暂停不可信的经纬度新目标与地理配准更新。GPS失锁与服务器断线是不同事件，服务器断线仍按第4节停车。

### 7.2 导入或重启后的重新定位

导入地图保留旧地图坐标，但不自动证明小车当前位姿。所有自主导航、返回Home与任务必须在当前扫描匹配、TF和定位健康检查通过后开放。

- GPS有效且地图已有有效地理配准：自动转换初始位置，结合可靠航向或静态雷达候选朝向匹配完成校准，优先不要求人工点选。
- 没有GPS、GPS不可靠或自动定位失败：提供上次保存位置辅助恢复、网页地图点选大致位置并拖动设置朝向、受限范围自动搜索。
- 地图没有地理配准：即使有GPS，也先在地图内重定位，再以可观测的位置和航向约束建立配准。

上次位置只是初始猜测。重复走廊或空旷区域可能有匹配歧义，不能承诺自动全局定位必然成功。网页显示GPS辅助定位、雷达匹配、成功或失败及具体原因。

单天线GPS静止时不能提供车头朝向；未经标定的IMU yaw也不能直接当作地理航向。启动可使用可靠绝对航向、双天线航向、静态雷达匹配或人工辅助。未定位时默认禁止移动；若使用人工遥控辅助，必须显式进入受限模式，并保留车体坐标下的碰撞和失联保护。

### 7.3 正常前进后的被动航向校准

系统不主动发起校准移动。小车因正常遥控或已获准的导航前进后，被动采集GNSS实际轨迹，在可信直线位移足够大时估计ENU行进方向，与相同时段、同一坐标参考下的估计朝向比较，显著且可信的偏差才进入校正。

使用时间同步、鲁棒窗口和环绕角差，检查GNSS质量、位移相对误差、里程计、IMU相对转角及轨迹一致性。排除静止、距离不足、跳点、倒车、弯道和明显侧滑；不能以收到前进命令替代实际直线运动证明。普通GPS可能需要更长的自然行驶基线，不为了凑基线额外移动。

先区分偏差来自航向估计、地图地理配准还是GNSS异常。通过定位融合或地理对齐估计器施加有界校正，不篡改轮里程计、静态TF或SLAM地图几何，不增加竞争TF发布者。大偏差且来源不明时暂停自主导航，验证后恢复。

无地理配准时不能直接比较ENU方向和map yaw；需结合可信地图内运动建立/验证配准。被动校准不解决“尚未定位便无法自主导航”的启动条件，不发布速度，不新增目标，不改变Home。

## 8. 导航点与Home

普通导航点保存地图位置、朝向及参考信息。每台车另有独立Home，它是特殊导航点，走同一导航、避障、脱困和状态反馈流程，不是特殊的直线返回控制。

Home默认对应首次上电位置，在首次有效定位后持久化；若定位建立前已经移动，只有能通过连续可信的相对位姿恢复起点时才初始化，否则提示未初始化，要求人工设置，不能把后来的位置冒充上电位置。设计默认后续重启保留Home，不自动覆盖。用户可显式将当前位置设为Home。

控制端可查看Home、设置Home、执行返回并取消。新返回命令替换已有导航前，先取消旧动作并确认终止，禁止并发。Home未设置、地图不匹配、坐标参考待核查、定位或连接不健康时拒绝执行并说明原因。执行中断线暂停停车，重连不自动恢复。

Home与导航点保存在车端，包含map_id、参考版本、位置、朝向、来源和时间。服务器读取和展示，修改以车端落盘确认为准。可靠GPS配准可附加经纬度用于展示，不能用不可靠GPS改写目标。设备切换不能沿用上一台车的Home或待发送命令。返回Home不包含充电桩对接。

## 9. 车端任务存储与调度

每台车的SQLite是任务定义、版本、启停状态和执行历史的唯一权威存储。服务器按robot_id读取列表、详情和运行状态；车端变化主动推送，重连获取完整快照。云端允许只读缓存，离线时标明缓存与最后同步时间，不能当作实时状态。

创建、修改、删除和启停通过服务器转发在线小车，车端事务落盘确认后才报告成功。离线修改明确失败，不在云端静默排队。

支持多条任务、单个或多个地图航点、启停、取消和历史。交互提供每隔N分钟/小时、每日HH:mm、每周及高级五字段cron；默认时区Asia/Shanghai，实施计划明确日期与星期匹配、夏令时和间隔基准语义。

每次执行及执行期间都检查服务器认证连接与心跳、地图匹配、定位、安全状态及控制仲裁。任务导航串行；手动驾驶优先暂停自主任务，释放驾驶后不自动恢复。断线禁止启动，执行中断线暂停停车，重连后需显式恢复。忙碌或断线期间错过触发记为跳过，不补跑；持久化执行实例唯一键去重。重启后结果未知的执行进入待核查状态，不盲目重发。

## 10. 云端管理车端地图

控制端通过服务器对指定在线小车请求清除建图、导出和导入SLAM。操作有ID、进度与结果，可在重连后查询；车端确认才算成功。

### 10.1 清除建图

界面明确显示目标设备和地图并要求确认。车端先停车、阻止新任务、暂停地图写入并保存恢复快照，再重置活动SLAM会话。创建新的地图身份，使旧Home、导航点和任务绑定失效；任务定义与历史导出不静默删除。重置接口按实际SLAM版本验证，不能将清除定位缓存当成清空地图。

### 10.2 导出

导出一致的完整地图包，包含：

- 可续建SLAM位姿图及关联扫描数据。
- 栅格地图与YAML、稳定障碍维护状态及必要的长期占据层数据、manifest、校验和、格式/ROS/SLAM版本。
- 地图身份、参考版本、坐标约定及传感器配置/外参摘要。
- 已有的地理配准，包括datum、高度基准、变换、航向约定、质量和来源；没有时明确标记unreferenced。
- Home和普通导航点，携带来源与地图绑定。

仅地图图片不足以恢复原位姿图继续建图。定时任务默认不随地图导出迁移，避免导入后意外执行。导出时最后位姿可用于提示，不能作为下一次启动的已知当前位姿。

### 10.3 导入

检查归档大小、路径、符号链接、校验和与格式兼容性，在隔离目录解包。通过后停车、备份旧地图并切换；加载失败恢复旧数据但保持停车待重定位。导入成功后按第7节重新定位，不能因包含GPS配准就跳过当前位姿验证。

同车恢复需核对地图身份与附属点；跨车导入的Home先作为待确认点，不自动成为本车Home。包内配置/外参仅作来源描述，不覆盖当前车的标定、尺寸、凭据或部署配置。GPS信息不是导入必要条件，无GPS也可通过雷达匹配定位。

## 11. 深度视频、识别与避障

优先使用WebRTC：车端编码、云端信令，提供STUN/TURN与coturn部署配置及短期凭证，支持4G/CGNAT中继。视频拥塞不阻塞控制，显示帧龄、延迟和连接质量。无相机时显示不可用，不伪造实时画面。

使用时间同步的RGB、深度、CameraInfo和有效外参，形成车体坐标下的三维几何障碍，输入代价地图与安全门。YOLO提供人员、车辆等语义，未识别类别的物体仍按几何避障。深度盲区、无效深度及遮挡需要明确处理，不能把无测量视为空闲。

提供CPU与可选硬件加速配置，负载过高优先降低识别频率，不降低安全保护频率。部署者提供模型权重并核对许可，权重缺失明确显示未启用。训练方案覆盖现场采样、标注、按场景/时间划分数据集、训练、导出、推理部署、漏检与运行负载评测。

## 12. 网页界面与交互

采用工业仪表台方向：石墨深色、暖白文字、琥珀控制强调、青绿色健康提示，急停为醒目的红色固定入口。地图为核心画布，显示轨迹、目标、Home、安全范围和定位状态。

桌面提供设备列表、地图、视频与驾驶区；导航点、任务、地图管理和设备配置作为清晰的独立视图。任务编辑以自然语言式选项为主，cron为高级入口。导入/清图展示影响，离线缓存与待确认状态有明确标记。

移动横屏以地图/视频和双拇指控制为核心，控制权、速度、数据帧龄与急停始终可见；竖屏适合监控和任务编辑。提供中文、可访问焦点、足够触控区域和减少动画支持。模拟数据显式标记演示，不将假电量、假识别或假地图当作实时硬件数据。

## 13. Linux仿真与验证

项目必须提供Linux中的仿真接入、启动配置、场景与验收方法，通过网页实际控制仿真小车。当前不需要连接、操作或索取用户虚拟机访问权限；今后实际联调时再配置访问方式。

完整链路为宿主机或其他终端网页 → 云端/自托管中转 → Linux虚拟机内车端代理 → ROS 2 → 仿真底盘。代理主动连接支持NAT，不依赖跨主机DDS发现。部署文档区分宿主机、虚拟机和云端地址，不能将各自localhost混用。

根据目标Linux中的ROS与Gazebo版本，接入已有模型或提供匹配的独立仿真。模型应体现senior_4wd_dl外形、差速运动学，以及雷达、RGB-D、IMU、轮速与可选GNSS。仿真GNSS来源于世界真值，不能从SLAM或轮里程计反推。实车与仿真配置分离。

ROS时间相关节点统一use_sim_time；网络租约、命令失效与连接保护使用单调墙钟。仿真暂停后旧命令仍会过期，恢复不得突然执行旧速度；处理/clock重置、倒退与仿真重启。

| 验证范围 | 关键场景 |
| --- | --- |
| 遥控与连接 | 按住/释放、失焦、断线停车、重连拒绝旧命令、切车隔离、多个页面控制互斥、仿真暂停恢复 |
| 导航与安全 | 贴墙后安全倒车、窄道、角点旋转风险、动态障碍、感知过期、四面受阻有界失败 |
| 地图与定位 | 保存重启续建、无GPS导入后定位、有GPS自动校准、损坏导入回退、清图后旧目标禁用、回环与地图扩展区分 |
| 航向校准 | 正常前进被动修正、短基线/噪声/倒车/弯道拒绝、不产生运动指令、坐标与环绕角正确 |
| Home与任务 | 起点初始化、重启保留、重设与返回、车端持久化、服务器读取、断线不执行、无补跑、执行去重 |
| 视频与识别 | 视频传输、深度几何避障、无效深度、模型缺失、推理负载与控制隔离 |

纯算法与业务测试覆盖几何、协议、配对码、连接与超时、数据持久化、调度和配准质量。Linux验证launch、ROS消息类型、TF唯一发布权、唯一速度输出与完整仿真场景，采集日志和结果。macOS单元测试不能代替ROS仿真与实车验收，也不能据此声称实车绝不碰撞。

## 14. 交付与边界

交付网页、云端服务、车端代理、ROS 2包与启动配置、Linux仿真模型/场景、协议与地图包格式、部署模板、硬件检测工具、训练方案和验收文档。开发过程中执行测试与静态构建，不擅自启动开发服务。

公网部署需要服务器、域名、TLS与TURN带宽，提供自托管方案，不代替用户购买资源。平面导航与现有传感器不能保证识别所有坑洞、台阶或悬空风险；实际触碰后不承诺任意方向都能自主脱困。

实施细节由后续计划明确：已安装版本的插件接口、配置阈值与实测制动能力、后端回环关联能力、稳定定位判据、调度边界语义和数据库/协议结构。Home跨重启保留、断线暂停且重连不自动续跑、地图包不默认迁移任务等为本文明确的设计默认，不作为用户已逐项指定的事实。
