## 实施方式

只有一条符合用户要求的正式路径：所有外部组件使用原有标准 ROS 接口，时间解释在本项目接入层完成，内部只保留一套明确的时间表示。继续强制第三方发布新消息、部署驱动补丁或保留标准/Timed 两套自动回退均不采用。

内部有界消息、来源绑定、序号与进程生命周期仍按职责存在；它们不能要求厂家配合新增字段，也不能被包装成另一套必须由驱动提供的时间证明。

## 统一时间规则

1. 标准消息 `header.stamp` 是测量时间坐标。保留原始整数纳秒值，不将其描述成精确硬件采集时刻；具体含义取决于已有驱动。
2. 在项目的首次原始消息接入处同时记录本地 ROS 时钟和单调时钟。实车同一连续时钟段内使用 `sample_steady = receipt_steady - (receipt_ros - header_stamp)` 映射，保留测量年龄，不能直接把接收时刻当测量时刻。
3. 映射与首次接收信息随内部记录传递，只计算一次；后续队列、过滤、估计、快照和 UI 不重新盖时间。相同发布者、同一时钟段内的重复样本不能因重收而变新。
4. 数据对齐与差分使用同一测量坐标的原始时间差。TTL、计算预算和队列等待使用本地单调时间，两类量不混用。
5. 时钟换段、倒退、时间戳无效或明显不属于当前时钟坐标时，撤销受影响窗口并说明原因。保留已有效的 0.3 秒软退化/1 秒硬失效等需求，不新加用户未要求的全车资格门槛。
6. 实车和仿真使用同一标准消息入口。仿真采用已有 `/clock` 与 `header.stamp` 作为测量坐标，内部记录 reset 段；零时刻合法，暂停不让旧样本反复变新，物理测量间隔不以主机经过时间替代。ROS/单调映射应由公共模块表达时钟模式，不能在每个订阅者中重新实现。
7. 没有 header 的标准命令消息只拥有项目首次接收时刻，不虚构第三方计算时刻。项目自身生成的最终命令仍保留内部计算入口和原始截止时间，并在实际发布前检查；不宣称已核验原厂串口执行延迟或硬件 watchdog。

公共时间模块须提供 C++ 与 Python 一致的规则与字段含义。具体类型名由实施计划锁定；不继续沿用 `SourceTime`/time_proof 的厂家证明语义，也不保留解析旧证明的分支。

### 仿真语义补充提案（待用户确认）

- 0.3 秒软退化/1 秒硬失效、消息排队和命令 TTL 按主机实际经过的单调秒计算；位移/速度积分仍使用消息 stamp 的仿真秒。稳定 10 倍速下，落后 1 个仿真秒的样本约落后 0.1 个主机秒，不能直接扣成 1 个主机秒。
- 公共映射模块记录有界的标准 `/clock` 与本地单调时间对应历史，结合消息 stamp 在首次接入时得到一次性的主机时间估计。历史边界与保留范围由既有年龄/队列窗口确定。该估计只反映本机可观察的时钟关系，不宣称恢复设备真实采集时刻。
- 暂停时相同 `/clock` 值不能持续覆盖其首次观察时刻；旧样本在主机时间中继续变老。暂停期间才到达的延迟样本仍按历史 stamp 映射，不能从到达时重新开始计算年龄。历史不足或映射存在歧义时标记不可用/采用能够证明的保守年龄，不用接收时刻伪造新鲜测量。
- reset 只保证覆盖本项目能观察到的 `/clock` 倒退、来源发布者换代和项目自身时钟段重新初始化。若将来已有项目 reset 入口被使用，必须同步清理窗口；本次不增加新的 reset 产品功能。
- 同一发布者的不可观察 0→0 reset，以及发生后在两次观察间已经追平的 reset，标准接口无法保证自动识别。撤销原引擎补丁对应的保证，删除仅为它们建立的测试和文档承诺，不保留引擎 hook、额外 reset 证明或自动回退协议。

## 完整迁移范围

### 原始消息接入

- `scan_receipt` 接回标准 `LaserScan`；`raw_receipt` 接回标准 `Image`、`CameraInfo`。
- 轮速/IMU 接入使用配置中的标准 `Odometry`/`Imu` 话题，原始 DDS 发布者身份仍能核实。原生接收进程、来源换代和有界队列可复用，订阅类型与时间记录必须迁移。
- GPS/AHRS 等可选源使用现有标准消息和现有配置，缺失仍按原需求退化，不强制新增设备。
- 激光过滤、扫描匹配、RGB-D、语义/深度候选和静态 TF 绑定统一消费内部首次记录的原始 stamp/接收时间，不解析驱动时间证明。

### 估计与控制

- MotionEstimation、PoseEstimation、SpaceEstimation、时间窗口、来源接纳和启动学习相关时间处理全部迁移。保留现有效的质量、来源、乱序、去重、重启、几何与算法行为。
- 独立车体速度仍由实际独立观测估计，不能用命令目标值或轮速伪造。错误原因继续区分缺数据、数据过期和几何/场景退化。
- `RawCaptureHeader` 等项目内部消息删除新增 `SourceTime timing` 依赖，保留必要的原始 stamp、首次接收和来源信息；派生记录使用统一内部时间接口，不重复出现另一套隐蔽证明字段。
- 最终输出 owner 使用原厂现有标准速度接口（当前 `/cmd_vel`），保持唯一最终发布者、原始内部命令 deadline、过期归零和关闭时归零。删除依赖厂家订阅 `ActuatorTarget` 的输出契约。
- Nav2 的结果/速度/定位接入使用原包标准接口，项目内处理导航生命周期、私有运行命令话题、截止时间与最终输出。禁止把 Nav2 直接接成第二个底盘速度 owner。
