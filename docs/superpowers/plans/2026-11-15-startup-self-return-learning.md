## 实际调用链

`motion_core_output._observation`（约708行）调用 `filter_self(scan,node._profile(),range_uncertainty)`，再将 external_hits 和 `scan_free_patches` 送入 `prepare_perception → SpaceEstimation → ConstraintSnapshot → ConstraintEngine`。后者 `_clear` 先判断完整 world sweep 是否与 occupied 相交，之后才检查移出当前车体部分的 free-space。内部未过滤 hit 因此令 `_stop_certificate` 返回 `stop_envelope_blocked`，即便外部有足够 free-space。不是 GPS 未初始化或传感器年龄造成。

现有 `self_filter` 用射线与手填 mask 的**交集**判 self。把 footprint 填到这个参数会使从车内起射的外部 hit 也消失；不能作为迁移方案。现有 filter 的 self 光束不生成 free；这一点必须保留。

## 拟实施的职责与步骤（尚未闭合首次运动条件）

1. `StartupLearningOwner` 独立管理初始化、静止采样、等待空间、前移、制动、验证、完成、歧义完成、中断、失败。程序 start 初始化完成后提出低速直行目标，目标行程 .15 m；只能走既有仲裁、轨迹、最终扫掠及急停输出。手动接管、急停、取消、观测硬失效、空间不足立即撤销启动目标并走停车，不恢复旧动作。
2. start 的可信运行代次由程序生命周期 owner 持有；在首次发非零目标**之前**写入已尝试标记。组件重建、重连不能再次创建启动任务；进程崩溃遗留尝试进入中断恢复，不自动重走15厘米。不能仅用 ROS 节点实例布尔值实现只执行一次。实际 start owner 和持久化接线仍需落地，本文不声称已接通。
3. `SelfReturnLearner` 消费前中后多帧、外参、统一估计原始 lineage/期限和误差。候选端点必须在物理 polygon 内，比较 body-fixed 与 world-fixed 残差及不确定性；外点永远作为外障碍候选。需要排除世界固定假设及匹配歧义才生成局部距离/空间支持模型，不按整个角度拉黑。平行墙、重复纹理、跟随外物、轮空转不能仅以残差小通过。轮/IMU只提供带滑移限制的预测，不冒充独立平移证据。
4. 过滤模型每次使用重新匹配局部端点和支持区间；端点移出、原设备消失、新近物或不一致立即撤销该项，遮挡后方保持 unknown。外伸设备不能被学习，仍需计入真实碰撞外形；用户本次确认设备均在边界内，无需额外设备几何输入。学习模型不修改 footprint 或激光外参。
5. 单天线 GPS 朝向是旁路观察者：累积直行有效位置/速度及精度，结合轮速有符号方向和 IMU 转角估车头朝向，倒车 course 加 π。精度不足或基线短保持未初始化，后续继续累积，绝不阻止相对估计或学习。复用统一 .3秒降可信/1秒失效及周期诊断，不添加年龄门。
6. 先完成下述首次运动可观测性决策，再实现 owner、学习模型、配置迁移及输出接线，随后验证急停/中断/一次性/崩溃恢复/内外点/遮挡/撤销/GPS。未闭合前不删除生产旧配置以留下半迁移链。

## 不能凭现有证据闭合的首次运动条件

定向测试在基线复现：车内 .15 m hit + 外界充分显式 free-space，.05 m/s 目标仍无 permit，原因为 `stop_envelope_blocked`。静止多帧的设备与同位置外物完全同观测，无法在首次运动之前取得运动分类证据。把未知内部回波暂时删除 occupied 等同于无证据特殊放行，违反本任务约束；把它改成 unknown 也不能把其遮挡后方的新增扫掠空间视为 free。物理 polygon 提供边界，不能凭它推出回波归属。

即使有办法开始移动，轮速与 IMU 在匀速滑移/轮空转阶段也不能独立证明 .15 m 平移；沿无限平行墙或重复结构的激光可能没有纵向辨识能力。运动设备与真实匀速跟随物也可能拥有相同 body/world 残差。此时必须输出歧义，不能伪造 learned 或独立位移；15厘米不保证分类成功。

负责人需要决定可接受的额外启动依据：例如已有可信且本次重新验证的设备模型、能区分内部回波的独立观测，或者明确修改首次运动允许处理的条件。这里没有要求另填 mask，也没有要求实车试走来取得开发许可。当前任务禁止无证据内部全忽略，现有输入又未提供其他归属证据，故不能诚实声称所有这类场景都能自动开始学习。应回报阻塞，不能用单独学习算法掩盖没有安全接线。

## GPS现状

`localization/heading.py::HeadingObserver` 是被动**校正**观察者，依赖 georeferenced map，拒绝倒车；不能直接充当启动绝对航向初始化器。其 `horizontal_std_m=None` 被当作精度合格，也不符合本任务未知精度不得可信的要求。现有 `motion/observations.py` 对GPS机体转换要求合格 Heading 上下文；新初始化器必须在此转换之前独立消费原始ENU，不形成 heading→GPS→heading 环。

本次搜索硬件审计及 hardware-motion.json 没有找到接收机型号、RTK实测精度或已配置 gps_input 的证据；不能声称具备 RTK，更不能保证15厘米足够。GPS部分尚未修改或接线。
