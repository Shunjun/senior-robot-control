# 启动学习旧文件一次清理

仅在现有程序启动owner内接线：硬件adapter身份验证成功、Agent已创建，事件循环处理一次退出通知后，受监督进程仍显示存活且未停止；仿真在同类边界、READY通知前。没有Agent应用层ready/云连接信号，不声称这些已经就绪，不增加固定等待延迟。服务现有独占锁仍持有，清理另外非阻塞持有同root另一类服务的既有锁，保护并行活跃运行。

独立runtime/learning_cleanup模块只枚举同一个打开的control root，精确匹配生产器生成的小写32hex claim，以及.features.json/.features.json.pending；保留当前run所有匹配配套，其他后缀不碰。不递归、不跟随链接、不删除目录。所有预期文件系统失败仅日志，不重试、不导致监督进程退出。仅成功边界调用一次，失败启动残留留给下一次成功启动。

不改变一次学习尝试语义，不修改已冻结第7项，不提前加入后续共享学习记录的格式或恢复逻辑。测试使用临时目录及假进程，集中覆盖白名单、当前保护、链接/目录、活跃对方锁、失败非致命、启动失败不清理及只调用一次；不提交推送、不启ROS/车辆/开发服务。
