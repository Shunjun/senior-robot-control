# 车端管理与 ROS 执行架构确认稿

本文记录本轮确认的架构边界。原《ROS2与车端架构重构讨论方案.md》保留供对照。功能分支 a445b1b 的代码可作为职责拆分参考，当前包内拆分尚未满足入口与功能包分离的目标。

## 确认的边界

- 仓库根目录的 `senior_control/` 是 ROS 外的车端管理子项目，拥有自己的源码、测试和构建配置。云端通信、任务接收与排队、设置、服务监管、日志归档与上报归这里。任务管理通过公开接口下发目标与取消请求，接收执行状态和结果。
- `ros2/src/` 放车辆执行功能包。现有 `src/senior_control/` 中属于执行的运动、感知、融合、导航、定位和建图逻辑，按职责与相应 ROS 入口、算法、状态和测试归在一起。
- `senior_robot` 和 `senior_sim` 是平行的实车／仿真入口。它们选择设备、参数及启动组合，共用功能包。功能包之间通过公开契约共享只读数据和提交请求，各自拥有可写业务状态。包和进程分别划界，保留确有用途的进程隔离。

## 功能规则

- 感知保留测量时间和来源。同一帧解码一次，复用只读几何。学习消费真实观测，避障可派生补点。耗时且同语义的运算优先收敛；简单局部操作保留。
- 自车运动估计融合轮速、雷达运动与可用 IMU，预留 GPS 速度观测。运动估计提供融合车速和连续本地运动历史。碰撞预测用测量时间和这段历史补偿障碍位置，再评估净距与风险。观测时间由消费算法解释。
- 运动控制拥有仲裁、限速及最终速度输出。MotionCore 负责轮次编排。独立守卫按序号执行最新合格包，用本地单调时钟监测断流。默认 20 Hz，五个配置周期即 250 ms，断流发零，后续新合格包可恢复。计算起点用于诊断，业务截止由上游处理。
- 定位通过实时扫描和稳定地图结构判断位姿偏差，环境变化由建图根据可信位姿、可见性和多帧证据处理。局部障碍与持久地图分开，全局纠偏与连续本地运动分开。
- 地图支持新建、保存、切换、删除及每图可编辑 Home，默认 Home 是建图开始车位。切图自动定位失败后，界面在 Home 显示待校准标记。用户提供车位初值，定位局部匹配微调；可信定位后恢复导航与持久写图。
- 导航保有原始目标，目标在未知区时通过可达前沿探索，地图扩展后重规划，全程经共用运动控制。
- GPS 先定独立观测契约，包含测量时间、坐标系、位置协方差及普通定位、RTK 浮点、固定解与无解。速度观测可选。位置由定位融合，速度由运动估计融合，设备安装后接入驱动。
- 诊断统一管理采集、关联、写入与轮转。业务路径用有界非阻塞入口，按模块、帧、任务及控制轮次关联观测、决策和耗时。

## 迁移范围与接口

- 本轮覆盖所有已实现链路。建图纳入本轮迁移与功能实现，包括已有实时建图和地图管理链，以及前文确认的地图操作、Home 和重定位协作。
- 导航保留在迁移范围内，已有接口及可运行链路在迁移期间保留。导航作为后续批次，新的前沿探索等算法在运动、定位、建图接口稳定后实现。
- ROS 按运动控制、运动估计、感知、导航、定位和建图拆分。回波学习与碰撞预测先作为感知内部独立模块。C++ 输出守卫归运动控制包并保留独立进程。GPS 先落观测契约，硬件驱动待设备接入。
- 车端管理程序优先通过现有本地 IPC 调用执行层。ROS 功能间按数据流选用 ROS 消息、服务、动作或进程内公开接口。云端与车端共用的契约独立，ROS 消息留在 ROS 侧。
